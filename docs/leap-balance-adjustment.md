# 飛躍条件・革新報酬の調整

GPT-6-Lunaの3エージェントへ候補A/B/Cをそれぞれ割り当て、訪問頻度・通常継承回数・革新投資順を変えた試験を依頼した。親エージェントが共通モデルで3候補を再比較し、Aをゲーム本体に反映した。別の6-Lunaエージェントに配布版のブラウザ再確認を依頼した。担当別の追加試験ログは [leap-agent-results.json](leap-agent-results.json) に保存した（担当ごとに訪問境界と投資順の条件が異なる）。

## 採用した数値

| 項目 | 調整前 | 調整後（A） |
|---|---|---|
| 必要累計 | 10^(18+6×飛躍済み回数) | 10^(18+3×飛躍済み回数) |
| 初回 / 2回目 / 3回目 | 10^18 / 10^24 / 10^30 | 10^18 / 10^21 / 10^24 |
| 革新報酬 | floor((1+log10(累計/条件))^1.3) | floor(3+log10(累計/条件)^1.3) |
| 条件ちょうど / 10倍 / 100倍の報酬 | 1 / 2 / 4 | 3 / 4 / 5 |

条件の指数上限240を維持。革新ツリーの価格と効果は据え置き。初回は基盤1ポイントと、量産革命または情報経済2ポイントを購入できる。計算理論3ポイントに向けて貯める選択も可能。後続の飛躍でも基本3ポイントを得る。条件ぴったりで飛躍すると枝を買えない空白を減らし、待って報酬を増やす選択も残した。

保存形式はv6のまま。所持ポイント・購入済みスキル・施設などを保持し、新条件と今後の報酬を適用する。過去報酬の差額は配布しない。旧スキップ退避状態の復元は当時の所持ポイントをそのまま復元する。新規スキップは自然な初回飛躍と同じ3ポイントで開始する。

## 3候補の共通比較

A=3桁増/3点、B=4桁増/3点、C=4桁増/5点。基本報酬以外の加算式・革新価格は共通。初回飛躍チェックポイントから開始し、8時間の訪問休止（生産継続）、各訪問3クリック、施設最大100個を限界生産/価格で選択、解放済み研究と安い下位スキルを購入する。通常継承は10ポイント以上で各飛躍間最大3回、革新は基盤→量産・計算・情報経済の優先順。待たず条件達成時に飛躍する。

表の時間は**初回飛躍後から**の暦時間で、初回飛躍までの時間を含まない。睡眠開始の16時間目にも最後の訪問を一度処理する共通モデル。

| 候補 | 15分訪問：2回目 / 3回目 | 1時間訪問：2回目 / 3回目 | 3時間訪問：2回目 / 3回目 |
|---|---|---|---|
| A（採用） | 8 / 24時間 | 24 / 57時間 | 48 / 126時間 |
| B | 25.5 / 97時間 | 30 / 96時間 | 72 / 168時間 |
| C | 25.25 / 96時間 | 30 / 85時間 | 72 / 160時間 |

C担当の追加試験では、初回5点は量産＋情報経済の両方を買えるため、この2枝を排他的に選ぶ差が薄くなった。計算優先は、1時間訪問・上限3で2回目33時間/3回目96時間と量産優先30/85時間より遅かった。初回3点で2枝から選ぶAの方が、序盤の投資判断を残す。

Aは1時間訪問の参考戦略で3日以内に3回目まで進む。B/Cは同条件で3日を超える。報酬を5点にするだけのCは、条件4桁増の待ちを十分には解消しなかった。初回を据え置きながら、飛躍後に何度か投資できるAを採用した。

Aの4回目は15分訪問131時間、1時間訪問151時間、3時間訪問は7日中に未達。全ツリーが即座に埋まる設定ではない。3日で不可説不可説転に至る最終目標は、この試験では達成・検証していない。

## エージェントによる追加試験

A担当は通常継承上限0/3/10、訪問15分/1時間/3時間、睡眠あり/なし、投資優先順を試験した。睡眠開始時の操作を省く別モデルも使ったため、上表とは数字を混ぜない。1時間・上限3では3回目59時間、上限10では99時間（7日試験）。継承しすぎて施設を失うと、飛躍が遅れる傾向が残る。15分・上限10では4回目50.25時間だが通常継承40回で、操作負担が大きい。

本体反映後にもA担当が共通スクリプトを再実行。1時間訪問・上限3の7日で、量産優先は2/3/4回目24/57/151時間、情報経済優先は48/85時間・4回目未達。終盤の購入ノードは同じでも、投資順の選択差が序盤に残る。

これらは購入操作をプログラムでモデル化した試験で、人間が実時間で1週間操作した記録ではない。訪問頻度や下位スキル投資の効果が大きく、最適戦略やカジュアルプレイの到達保証はしない。

## 表示・検証

飛躍後はメイン進捗に次の飛躍条件と割合を表示。革新画面に未使用ポイント、次の取得方法、現在の累計/必要累計を表示する。スキップの説明も3ポイントへ更新。基盤購入後の2ポイントで選べる枝が分かる状態にした。

自動テスト18件が成功。新しい条件の境界、条件達成時/10倍/100倍の報酬、初回分岐の排他購入、既存v6資産を変更しない保存読込を追加検証した。`game.js` と単一ファイル版 `play.html` を再生成。親エージェントはHTTPで両ページの新規スキップ→基盤購入→残2ポイントと両枝の候補表示、次の条件10垓（10^21）、スマホ390×844で縦横とも画面内に収まることとJavaScriptエラーなしを確認した。開発用HTTPサーバーが応答しなくなっていたため再起動し、ポート3000の配信を復旧した。

6-Lunaの最終ブラウザQAも完了。PCのindexとスマホの単一ファイル版で、1e21の有効なv6途中セーブから2回目飛躍の確認/実行（+3）、次条件1e24・0%への更新を確認。新規スキップ→基盤＋情報経済→残0→再読込で保持→退避前の進行復元も成功。スマホ説明行のはみ出しとページエラーはなし。途中セーブ投入は待ち時間を省く表示/操作試験であり、自然進行の時間計測とは区別した。

## 再現方法

```sh
npm test
node scripts/playtest/leap-candidates.mjs --days 7
node scripts/playtest/repeat-leaps.mjs --interval 3600 --inherit-max 3 --days 7 --innovation economy
node scripts/playtest/repeat-leaps.mjs --interval 3600 --inherit-max 3 --days 7 --innovation discount
```

`leap-candidates.mjs` は一時ディレクトリに候補エンジンを生成して比較し、終了時に削除する。ゲームソースや保存領域は変更しない。候補共通9ケースの実測出力は [leap-balance-comparison.json](leap-balance-comparison.json) に保存。

残る課題は通常継承のやめ時の案内、情報経済の序盤の弱さ、4回目以降の間隔、3段目以降と大数演算。今回の条件・報酬調整から独立して、次のテストで扱う。
