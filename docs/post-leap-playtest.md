# 飛躍後の目的別テストプレイ

> 以下の進行ペースは今回の飛躍調整前（6桁増・基本報酬1）の記録です。最新結果は [leap-balance-adjustment.md](leap-balance-adjustment.md) を参照。再現スクリプトは現在のエンジンを使うため、当時の数値と一致しません。

GPT-6-Lunaの4エージェントに、立ち上がり・革新投資・再飛躍・操作負担を分担した。ゲームの数値・セーブ・UIは変更せず、診断スクリプトとこの記録を追加した。代表値は親エージェントでも再現し、融合の前提不足と睡眠境界に関する初期報告は訂正した。

## 前提と限界

数値試験は原則、初回飛躍直後のテストチェックポイントから開始する。表の時間は初回飛躍後からの暦時間で、初回飛躍までに要する時間を含まない。訪問間は通常速度で生産し、訪問時だけ施設・研究・スキル購入・転生を操作するモデル。ゲーム本体には自動購入機能を追加していない。手動操作の所要時間はモデルに含まない。

モデルごとに研究と時代進行の反復回数、購入順、睡眠境界での最終操作が異なるため、別モデルの数字を一つの厳密な最適戦略として比較しない。初回飛躍に実際に至ったプレイヤーは操作履歴等が異なる。長期試験や途中セーブ投入は実際に何日も人間が操作した記録ではない。

## 1. 飛躍直後から情報施設まで

基盤購入後、通常継承は一度もしない。人間向けモデルは新しい施設を優先して1訪問につき4購入操作、各10個まで。ROIモデルは限界生産増加/価格順で最大100個購入。手動採集なし。1時間ごと訪問、毎日8時間訪問を休む（生産は継続）。

| 指標 | 人間向けモデル | ROIモデル |
|---|---:|---:|
| 情報時代 | 4時間 | 4時間 |
| 最初の計算機センター | 4時間 | 12時間 |
| 計算機センター10個 | 6時間 | 14時間 |
| 3日後の情報施設数（計算機/データ/AI） | 18 / 2 / 0 | 17 / 3 / 0 |
| 7日後 | 23 / 3 / 0 | 21 / 3 / 0 |
| 計算機センター25個 | 288時間 | 480時間 |
| 30日後 | 26 / 5 / 0 | 26 / 5 / 0 |

入口より積み増しが遅い。情報施設の購入ごとの価格増加1.4倍と、次施設への1000倍の価格差が大きい。ただし通常継承による下位スキルの再育成を省いた試験なので、全プレイヤーがこの時間待つという結論ではない。

睡眠なしよりありの方が早くなるケースも出た。休んでいる間の貯金により高い施設を買い、細かい訪問で安い施設へ使い続ける方針を回避したため。睡眠の生産ボーナスはない。訪問頻度だけでなく、貯める目標と投資方針が強く影響する。

## 2. 通常継承と再飛躍

3クリック/訪問、8時間睡眠、最大100個購入/訪問。通常継承は10ポイント以上で、飛躍ごとに最大10回に制限。安い解放済み下位スキルから購入する。以下は「各周回の最大10回」という一つの策略で、最適解を保証しない。

| 訪問間隔 | 条件達成で2回目飛躍 | 条件の10倍まで待って飛躍 |
|---|---:|---:|
| 15分 | 81.5時間 | 148.5時間 |
| 1時間 | 63時間 | 84時間 |
| 3時間 | 144時間 | 156時間 |
| 獲得革新 | 1ポイント | 2ポイント |

飛躍条件は初回10^18、2回目10^24、3回目10^30。基盤に初回の1点を使うため、2回目を即実行しても累計残額は1点で枝は買えない。10倍待ちの2点なら量産革命を購入し、全生産5倍で次周回を開始できる。

1時間訪問の7日後、即飛躍策略は3回目条件に対し周回累計1.79×10^25、10倍待ちは9.40×10^25。30日後はそれぞれ5.14×10^26（条件の0.0514%）と7.86×10^28（7.86%）。15分・1時間・3時間の代表6ケースすべてで、3回目飛躍は30日以内に未達。

無継承では15分訪問でも30日以内に2回目未達（累計2.19×10^21/必要10^24）。一方、10ポイントで無制限に継承し続ける策略も30日で977継承に達し、周回累計を積む前にリセットするため2回目未達。継承は必要だが、その停止判断も必要。

15分より1時間訪問の方が早いのは、後者が継承前に多く貯め、飛躍前の下位スキルが19レベル（前者17）になった影響がある。頻繁に触るほど速くなる単純な関係ではない。

## 3. 革新の選択差

基盤以降の最初の価格は量産2点・計算3点・情報経済2点。条件ぴったりの飛躍報酬は常に1点で、初回・2回目には選択を始められない。

単一施設の革新適用前生産を10^11/秒とした理論比較では、基盤のみを基準に量産Lv.1は5倍、計算Lv.1は約2倍、情報経済Lv.1は生産を直接増やさず購入費20%減。初期の量産が強く、計算の効果は生産規模が増すほど強くなる。

融合は量産Lv.2＋計算Lv.1が前提。合法構成の必要総額は基盤含め20点。基盤に対する生産倍率は同じ施設規模で約253倍。前提を満たさない構成の初期計測は破棄した。

追加ポイントを人工付与する理論試験（自然取得ではない）では、基盤以外に8点を量産Lv.2へ使うと次飛躍条件に158時間、19点で合法融合を完成すると6.5時間。計算・情報経済中心は同試験の14日以内に未達。融合前後の差が大きく、追加ポイントの供給がボトルネックとなる。

## 4. 操作負担と目標表示

PC1440×1000・スマホ390×844でスキップ→基盤→施設購入→タブ切替をブラウザ操作した。途中の表示確認にはエンジン由来のセーブを独立ブラウザ領域へ投入した。JavaScriptエラー・横はみ出しなし。

- 飛躍後の工業以前の技術は習得済みなのに、空一覧で「施設を増やすと研究」、施設にも「技術が解放」と案内し、次の行動を誤解させる。
- 革新画面でポイント不足になっても、次の取得方法と飛躍条件を同画面から確認できない。
- 情報時代でもメイン進捗は「継承解放100%」。次飛躍の目標は別タブ下部にあり、スマホでは約5画面分の内部スクロールが必要な状態があった。
- 最大購入は簡単だが、買う個数と総額のプレビューがない。テスト状態では採集隊360個を1操作で購入でき、残高の多くを消費した。

## 改善の優先順位

1. **革新の選択が始まる報酬設計**：初回の基盤後、2回目までに枝を買える報酬/価格にする。「条件ぴったりは1点」のまま進むことが不利な構造を弱める。
2. **3回目以降の必要累計**：毎回6桁増加を、革新による実際の加速幅と照合して再調整。2〜3桁増などは候補であり、今回の試験では未検証。
3. **貯金と継承の目標を表示**：次飛躍の必要累計・割合、革新獲得先、下位研究習得済みをスコア/革新画面に表示。
4. **情報施設の積み増し**：報酬と飛躍条件を先に調整した後、価格増加率・研究倍率・基礎価格を再試験。すべてを同時に下げると問題の原因が分からなくなる。
5. **投資の選択差**：量産・計算・情報経済を同予算で再比較。融合の大きな加速は上位報酬として残すか、段階化するか検討。

## 再現

ゲームの保存領域を触らない診断スクリプト。`null`や到達時刻がない項目は指定期間中未達。

```sh
node scripts/playtest/post-leap-start.mjs --days=3 --interval=3600 --sleep=true --policy=human
node scripts/playtest/post-leap-start.mjs --days=30 --interval=3600 --sleep=true --policy=roi
node scripts/playtest/innovation-effects.mjs
node scripts/playtest/innovation-campaign.mjs
node scripts/playtest/repeat-leaps.mjs --interval 3600 --inherit-max 10 --leap-multiplier 1 --days 7
node scripts/playtest/repeat-leaps.mjs --interval 3600 --inherit-max 10 --leap-multiplier 10 --days 30
```

後者のcampaignはポイントを人工付与する14日試験。人間のテストプレイ時間の保証や最適戦略の証明ではない。現行の「3日で不可説不可説転」目標は達成できるバランスになっていない。

再飛躍の6代表試験の出力は [post-leap-results.json](post-leap-results.json) に保存。無継承は `--inherit-max 0`、無制限継承は `--inherit-max unlimited` で比較できる。
