# 反復超越と1e68到達のバランス

`transcendCheckpoint()`（初回超越直後、Horizon 1）から開始し、初回の「宇宙の基盤」を即購入しました。通常継承・通常飛躍・手動採集は使わず、訪問時に研究・進化・限界生産/価格が最大の施設を最大100回購入します。条件成立時は毎回すぐ超越し、Horizonの使い方だけを「次元優先」と「時空の圧縮優先」で比較しました。睡眠中も生産を続け、16時の訪問を飛ばします。

| 訪問間隔 | Horizon投資 | 1e68到達時の総超越回数 | 初回checkpoint後の超越回数 | 到達時間 |
|---|---|---:|---:|---:|
| 15分 | 次元優先 | 4 | 3 | 11.25h |
| 15分 | 価格割引優先 | 4 | 3 | 27.75h |
| 1時間 | 次元優先 | 4 | 3 | 30h |
| 1時間 | 価格割引優先 | 4 | 3 | 36h |
| 3時間 | 次元優先 | 4 | 3 | 60h |
| 3時間 | 価格割引優先 | 4 | 3 | 87h |

目標はすべて総超越4回で達しました。条件は順に1e40、1e50、1e60で、次の1e70より先に1e68を越えています。施設ゲートは追加せず、`facilityUnlocked(s,i)` は時代による制限だけを使います。銀河演算網の価格は1e62、生産は1e44です。

次元+0.15は強すぎる可能性が高いです。初めて購入した次元1レベルで、その時点の施設生産が約251倍になりました。最初の超越後の次の超越までの時間は、15分訪問で次元優先1h・価格優先16h、1時間訪問で4h・15h、3時間訪問で12h・30hです。次元優先は1e68到達を約1.2〜2.5倍早めています。価格割引優先も十分に目標へ届くので選択差はありますが、同じHorizonを使う選択肢としては差が大きめです。

次元レベルの指数加算を+0.15から+0.05〜+0.08に下げる案が妥当です。生産計算は施設の生産基礎値を指数で累乗するため、+0.15は開始施設だけでも数百倍に増幅されます。費用2,4,8,16を維持するなら加算を下げる方が比較しやすく、加算+0.15を維持するなら費用を上げる調整も候補です。この提案値自体は今回の実測ではありません。

結果詳細は [repeat-transcend-results.json](repeat-transcend-results.json) に保存しています。再現コマンド（リポジトリルートから）：

```sh
node scripts/playtest/repeat-transcend.mjs --interval 900 --days 90 --sleep 8h --purchase-limit 100
node scripts/playtest/repeat-transcend.mjs --interval 3600 --days 90 --sleep 8h --purchase-limit 100
node scripts/playtest/repeat-transcend.mjs --interval 10800 --days 90 --sleep 8h --purchase-limit 100
```

実装ではユーザーの「次元を強化」「4回程度で到達」という意図と6ケースの達成結果を優先し、+0.15と価格2・4・8・16を採用した。上記の弱化案はエージェントのレビュー提案として記録し、採用していない。
